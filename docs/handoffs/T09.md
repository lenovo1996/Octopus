## Điều hiện đã hoạt động

- `index_stage` / `index_unstage` (BE `src-tauri/src/commands/stage.rs`):
  WriteContext (`expectedVersion`) + pathIds exact, trust-gate trusted-only.
- Trình tự mutation: recheck version → resolve tất cả tokens trước khi đụng
  queue (all-or-nothing input) → lock per-common-dir queue (linked worktrees
  chung queue) → một lệnh Git duy nhất (`add` / `restore --source=HEAD
  --staged` / `rm --cached` khi unborn) → bump version + snapshot mới.
  Thất bại cũng bump + refresh listing để tokens cũ không còn hiệu lực.
- Không dùng `GIT_OPTIONAL_LOCKS=0` cho mutation (spec §1 cấm); không shell;
  argv `OsString` + magic `:(literal)` (kế thừa từ T08).
- Stage chỉ truyền new-side (rename chưa stage là 2 rows D+??; add old thừa sẽ
  fail); unstage truyền cả old+new để không sót half-rename trong index.
  Đã chứng minh bằng tay: `git add new` đơn lẻ KHÔNG stage deletion của old.
- Unstage không bao giờ đụng worktree bytes (restore --staged / rm --cached);
  unborn unstage giữ file trên disk.
- FE: nút Stage/Unstage selected theo checkbox, disabled khi chưa chọn/đang
  chạy/chưa có listing; lỗi giữ nguyên selection + reload listing lấy tokens
  mới; stale selection abort + refresh. Mock adapter có index in-memory để demo.
- Runner `run`/`run_with_env` dùng `AsRef<OsStr>` từ T08 (callers `&[&str]`
  compile nguyên).

## Quyết định và thay đổi contract

- `build_snapshot` lên `pub(crate)` để stage tái sử dụng.
- Stage/unstage trả snapshot trực tiếp (lifecycle-style, theo bảng IPC "Fresh
  snapshot"), không qua job registry — queue + version check đủ cho local ops.
- Giới hạn 1000 pathIds/request chống abuse.

## Blockers / known issues

- Visual native chờ user confirm chung gate.
- Concurrent edit ngoài app giữa resolve và git run được chấp nhận (có kiểm
  soát + refresh) theo đúng engine §2; không tự retry mutation.
